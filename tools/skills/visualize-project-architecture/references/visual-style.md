# 図解の見た目の決まり

図解の配色と質感を、会話の記憶に頼らずに再現するための決まり。色の値の正本はワークスペースのいちばん上の `DESIGN.md`（標準テーマ）で、ここには色の値を書かない。決めるのは見た目の言葉で、情報の構造ではない。図法・パネルの数・配置・情報の量は、対象の関係に合わせて毎回設計する。

## 優先順位

1. 本人が今回はっきり指定したこと、または見せてくれた参考の画像
2. 本人が了承して保存したデザインの設定（`tools/design.md` の手順で決めたもの）
3. `DESIGN.md` の標準テーマ

上位の指定を使った時は、設計（`project-overview-plan.md`）に根拠を書く。会話だけに出た好みは再現の条件にしない。

## `DESIGN.md` の色の使い方（4K の図解）

- キャンバスは `bg`（クリーム）の地にする。外周の `frame`（オリーブ）の枠は必須ではない（`DESIGN.md` は厚い緑の枠を図解に強制しない）。まとまりを見せたい時だけ、情報の面を圧迫しない太さで使う。
- 大きな区画はクリームか白に近い面、主なカードは `card`（白）と `card-line` の細い枠、まとまりの補助の面は `badge-bg` を使う。
- 文字は `ink`、補足だけ `ink-soft`。
- ふつうの流れ・確かめたこと・主な境界: `frame`（オリーブ）。
- 強調・戻ってくる結果・注意・変わった所: `accent`（ラストオレンジ）。画面全体の一部に限る。
- 管理・非公開・補助の流れ: `bar-c`（薄いオリーブ）か `ink-soft`。
- 3 つ目の意味が本当に要る時だけ落ち着いた別の色を 1 つ足し、凡例か線のラベルで役割を書く。

## 面と形

- 角丸は `DESIGN.md` の値（カード 10px・注意枠 8px・バッジ 4px）を基準にする。大きな箱をすべて丸いカードにしない。
- 影は原則なし。前後の関係に必要な時だけ、ごく薄く使う。
- ブランドの帯やロゴの帯を、頼まれていないのに足さない。

## 文字と線

- 矢印は色だけに頼らず、実線・破線・ラベルを合わせて意味を分ける。
- 線と境界は `card-line` を基準にし、大事な境界だけ `frame` で強める。
- 最小 28px、ふつうの本文 32〜36px というスキル本体の読みやすさの基準を優先する（`DESIGN.md` の 15px は画面・資料向けの値で、4K の図解には使わない）。

## 避けること

- 中身と関係の無い寒色のグラデーション、光る表現、ガラスのような透け。
- すべての要素への強い影。
- 色の数を増やすためだけの分類の色。紫のグラデーション、意味の無いアイコン、絵文字、背景の柄。
- 標準テーマらしく見せるための決まったレイアウト。見た目はそろえても、情報の関係は変えない。
