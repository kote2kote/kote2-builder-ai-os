# 保存状況を見せる

「保存状況を見せて」と言われた時、またはセーブの後で対象の保存範囲を確かめる時に読む。診断そのものは保存操作をしない。

```sh
python3 -I tools/save_status.py --ws .
python3 -I tools/save_status.py --ws . --project projects/monthly-report
python3 -I tools/save_status.py --ws . --project projects/monthly-report --json
```

`--ws` は確認済みのワークスペースのルート。案件を直接開いている場合は親のルートと道具への実際のパスを指定する。`--project` はそのルートからの相対パス。省略時は `wiki/projects/` 直下の案件ページの既存 `path:` だけを調べる。索引・本文のリンクから外部を探索しない。登録のない案件を自動登録せず、所在なしの相談ページにも新しい必須欄を足さない。

## 結果の読み方

- **親Wiki**: ファイルが存在すること、親Gitの最新commit、`wiki/` に関する最後のcommit、追跡中の項目と未commit・未追跡・ignoredを分ける。親Gitに別の変更があっても、Wiki内の状態とは混ぜない。
- **成果物**: 案件フォルダの存在だけで保存済みとしない。独立Gitの履歴と未commitを別に確認する。`projects/` は通常、親Gitの対象外。親Gitのサブフォルダでしかない場合は `not_independent`、Gitが未作成なら `not_initialized`、初回commit前なら `unborn`。空のrepoや追跡0件を成果物の保存済みとしない。
- **別媒体**: CLIはバックアップ先を探索せず、常に `not_checked_user_report_separate` を返す。必要なら該当案件Wikiの既存「保存と復旧」と今回の本人発言を照合し、「外付け媒体にコピーしたとの本人申告（確認日・対象範囲）、実物は未確認」のように補う。記録がなければ未確認のまま。申告から実測や復元確認へ読み替えない。新しい記録形式・DBは不要。
- **復元**: 常に未確認。Gitがあること、ローカルの追跡refが一致すること、本人のバックアップ申告は、復元試験の成功を意味しない。復旧は従来の手順と了承範囲で別に行う。

`changes` の stage/未stage は未commitの変更。`untracked` と `ignored` は履歴へ保存された項目ではない。件数はGitの項目数で、未追跡やignoredのディレクトリを1件と数える場合がある。`tracked_clean` は追跡中の変更が見つからないという意味だけで、未追跡・ignoredの保存を保証しない。Gitが検査対象から外した項目（assume-unchanged/skip-worktree等）やファイルの完全性も保証しない。ファイル数は本文を読まずに数え、2万項目を超えると `partial_limit` にする。

上流は手元の追跡refだけ。先行/遅れ0でも「今リモートへ保存済み」と言わない。fetchしないため古いことがある。`no_local_upstream` は参照先なし・削除済み・未取得・HEAD切離し等を含み、リモート設定がないとの断定ではない。remote URL、ref名、作者、メール、commit本文、Gitのエラー原文は表示しない。表示用パスも特殊文字等があれば伏せる。

## 未確認で止める境界

- ワークスペース外の登録値・`..`を含む案件path・symlink/junction・存在しない場所は追わない。不正な登録値は表示にも戻さない。Git管理先に相対参照がある場合も、`..`で正規化する前に各要素のリンクを検査する。ルート自体がsymlinkなら実在するルートでの依頼かを確かめる。診断がリンクを作ったり解除したりしない。
- `.git` ファイルを未初期化と取り違えない。管理領域もワークスペース内で、リンク等がないと確認できるものだけ読む。`commondir` が確認できれば `worktree`、外部を指す場合は `git_file / outside_workspace` のまま未確認。外部管理領域を読めるように移動・コピーしない。
- Git不在、所有者エラー、壊れたGit、読み取り失敗、時間切れは未確認。safe.directoryや権限の変更、Git初期化はしない。
- 設定のinclude・filter・別worktree指定・partial clone・外部object参照、Git管理領域内のsymlinkや特殊ファイルは未確認にする。診断中の外部処理や暗黙の取得を避けるため。Gitは各呼出し5秒で打ち切り、環境からのGit操作指定を除き、任意ロック・fsmonitor・hooks・署名検証プログラム・自動保守を抑止する。ユーザー/システムのGit設定と外部attributes/ignoreを使わないので、普段のGitとignored判定が違う場合がある。
- submodule内部・案件内の別repoの履歴・外部サービス・ファイルの意味や完全性は未確認。診断は同時編集を固定するスナップショットではない。大量のGit管理ファイルは2万項目で未確認にする。

JSONの `git.state` が `checked` でも、すべて保存済みの総合判定ではない。`files`、`changes`、履歴、未確認を合わせて読む。終了コード0はレポートを作れたこと（未確認を含む）、2は入力・登録・診断入口の失敗。エラーは固定の理由だけを出し、失敗した引数や例外本文を会話へ貼り直さない。

## セーブの返答

既存の `wiki/README.md` の保存前確認・対象を限定した保存動作を保つ。診断を理由に一括commit・push・設定変更をしない。保存後は **Wiki → 成果物 → 残り** の順に、確認できた範囲だけ短く返す。

例: 「Wikiの判断と次の一手を履歴へ保存しました。成果物はファイルがありますが、案件Gitには未commitの変更が残っています。別媒体の保存と復元は未確認です。」

Wikiのファイルだけ書けて履歴保存ができなかった場合は、その違いも明示する。新しいバックアップ作成や復元の実行、通信・常駐監視はこの手順に含めない。
