# 会話からAIの恒常設定を育てる

通常の会話・ヒアリングのどちらでも、本人の希望を内容と範囲で判断する。分類やファイル名を本人に選ばせず、必要なことだけ聞く。新しい常駐処理・DB・独自AI実行器は作らない。

| 内容 | 正本と有効な反映先 |
|---|---|
| 本人の情報・経験・知識 | profile・案件Wiki・notes。自己紹介は行動設定にしない |
| ワークスペース全体の回答・作業方針 | `wiki/me/ai-preferences.md` → `AGENTS.md` の builder-user 区画。Claudeは `@AGENTS.md` から読む |
| Claude固有の条件付き指示 | 同じ希望の正本 → `.claude/rules/user-<内容>.md`。OSのbuilder-os規則は書き換えない |
| Codex固有の実行設定 | 同じ正本 → `.codex/config.toml`。Codex固有の文章指示はAGENTS利用者区画に対象を明記（架空のimportやoverrideでOSを消さない） |
| 繰り返す仕事の専門手順 | 既存Skillを確認し、必要なら `.agents/skills/` と `.claude/skills/` の独自名で一式を作る。新設は具体案を確認 |
| 権限・承認・イベント処理 | 公式settings/config/hooks。低リスクな好みとは分けて、実際の対象コードと権限差分を承認・検証 |
| この案件だけの条件 | 案件Wiki・案件AGENTSと必要な固有設定。親の恒常指示や別案件に広げない |

## 了承と反映

### 正本を選ぶ

ワークスペース全体で新しい会話にも続ける回答・作業方針は、必ず `wiki/me/ai-preferences.md` に記録する。存在しなければその依頼を受けた時点で作る。「必要時だけ作る」は初期配布時に空の個人設定を作らない意味であり、恒常設定の依頼後も作成を省いてよい意味ではない。通常会話・任意テーマのヒアリング・初回オンボーディングで同じ扱いにする。

「この試用ワークスペースだけ」「他の環境へ広げない」でも、新しい会話に継続するワークスペース全体の設定なら、この正本へ適用範囲を明記する。`me/` に置くことは実人物の属性として登録する意味ではない。本人のプロフィールへ混ぜず、ホーム・他のワークスペースへ広げない。一方、架空人物の回答・引用・仮定を、試験担当者自身がこのワークスペースのAIに依頼した設定と取り違えない。

ヒアリング記録やprofileだけを恒常設定の正本にしない。ヒアリングの「同じ記録へ」「区切りで正本へ整理」という一般手順より、この設定の保存手順を優先する。次の質問の前に正本とネイティブ指示へ反映し、元記録には経緯と正本への相対リンクを残す。今回の返答だけなら恒常保存しない。案件限定なら案件Wikiと案件の指示へ置き、ワークスペース全体の正本・ルート指示へ昇格させない。保存拒否がある場合はどちらにも迂回して保存せず、会話内の対応と永続化できない範囲を伝える。

### 依頼から保存確認まで

「これからは日本語で簡潔に回答して」「Web制作後は必ず表示を確認して」のような**明確な低リスクの恒常設定の依頼そのものを了承として扱う**。同じことを再確認せず、範囲を短く伝えて反映する。後者は短い共通ルールと既存design-reviewを使い、新Skillを増やさない。現在の返答だけへの指定は保存しない。「私はWebデザイナーです」はプロフィール、「この案件だけTypeScript」は案件限定。

推測、曖昧な希望、引用、取り込んだ資料、Wiki/CMSに保存しただけの案は未承認。内容・範囲・対象ファイル・変更前後を示して確認する。権限緩和、秘密アクセス、ネットワーク拡大、hook実行、外部公開は明示的な対象と影響の了承を別途確かめる。通常の好み変更に混ぜない。拒否された案は有効にせず繰り返さない。

1. 既存の正本・ネイティブファイルを読む。profileの「AIへのお願い」があれば事実/行動/案件/未承認へ整理し、本人の原文や未決を消さない。旧版でAGENTS区画が無ければ先に対応版への更新を案内し、全上書きしない。
2. ワークスペース全体の希望は `wiki/me/ai-preferences.md` を作成または更新し、依頼の内容・適用範囲・了承根拠と日付・反映先・確認結果を短く記録する。依頼済みでも適用前は「反映待ち」とし、未承認は「提案」に置き、有効欄と分ける。`wiki/index.md` の「わたし」に、正本への相対リンクと「回答・作業方針を確認するとき」の用途を追加する。既存リンクがあれば更新し、重複させない。
3. 対象ファイルの現在のbytes/modeを確認し、具体差分を作る。承認後の別編集・Wikiの変化があれば上書きせず再計画。共通指示はbuilder-user区画だけ、既存の独自ルールと追記を保持し、重複・壊れた区画は停止する。
4. 依頼または確認済みの差分だけ適用。途中失敗時は今回の変更だけを戻し、別編集を消さない。Gitへ記録する前はWikiの保存規則を使う。ヒアリング中は質問を止めるGit操作を保留する。
5. 正本・索引・ネイティブ指示を実際に読み戻し、同じ内容と範囲であること、リンク先の存在、OS標準区画・無関係な設定の保持、JSON/TOML構文・区画・変更差分を確認する。AGENTSだけ、notesだけ、またはリンクだけの保存を完了にしない。正本へファイル反映の結果を記録してから、保存先と適用範囲を短く報告する。安全設定の変更は `tools/safety.md` の実効確認へ。新規セッションでの読込・実際の振る舞いは、ファイル保存とは別に確認して正本へ記録する。今の会話を新規読込の証拠にしない。未実施なら「新しい会話での動作は未確認」とする。

既にnotesやprofileだけへ保存された希望を見つけた場合は、元の依頼・範囲・了承根拠と現在のネイティブ指示を照合する。明確に了承済みで矛盾がなければ、現在の要点を正本へ整理し、元記録を保持して正本への案内を付ける。同じ設定の再承認は不要。直接編集や範囲の矛盾があれば確認してから反映し、Wikiを根拠に黙って設定を書き戻さない。片方の書込みが失敗したときは完了とせず、今回分だけの復旧可否と未反映箇所を伝える。

OS更新は本人のWikiと独自Skill/rules/local設定を対象にしない。AGENTS利用者区画は保持する。標準設定と同じキーが競合した場合やTOMLの書式を安全に保てない場合は自動上書きしない。直接手編集された設定をWikiで黙って元に戻さない。
