# Windowsの旧版から更新する前に

**4.5.2から、macOSなどの4.0.0〜4.3.0も、この4.3.2を経由します**（下の説明のうち、確認の窓や端末入力などWindows固有の部分は、Windowsだけに当てはまります）。

修正版の移行準備版は **4.3.2** です。取得前に、配布者の外付receiptで公開先・完全commit・配布一覧hashを確認してください。未公開のローカル候補を本番へ適用してはいけません。公開状況はreceiptで判断し、この文書の日付だけで公開済みとみなしません。
公開済み4.3.1の固定commit `fd8aa58cfdb8de30b210f626521605c3a07af91a` は変更しませんが、native Windowsには共通sandbox必須設定が残るため、この経路は推奨しません。旧版の拒否を手コピーや未導入コードの実行で迂回しません。

## 移行順と承認

native Windowsの4.0.0〜4.3.0は **4.3.2 → 最新** の2段階です。4.4.0や途中の版は経由しません。4.3.2の更新器は、4.3.2より新しい公開版へ直接更新します。公開前に、4.3.2から最新へ直接更新した結果が、途中の版を順に入れた結果とファイル・mode・利用者ファイルまで一致することを、架空の作業場で確かめています。4.3.2の公開完全commitを外付receiptで照合し、固定配布一覧のhash・実取得・各段階のcheckが確認されるまでは実環境で進めません。開発commitをpublicの取得先に使わないでください。

公開後は導入済みの信頼済み取得器だけで `python3 -I tools/release_package.py fetch --ref <確認した公開完全commit> --ws .`。抽出先・版・plan・配布一覧hash・全差分・保全方針を本人に説明し、次の返事のOKを待ちます。導入済み更新器の `apply --from <その抽出先> --ws . --plan <そのplan>` を使い、各段階で本人が正式確認を行います。4.1.0のWindows初回は本人自身の対話端末で「更新する」と入力する旧方式です。AIの端末・パイプ・偽窓・代理入力で代用しません。4.3.2以降はWindows確認窓です。キャンセル・timeout・確認不能・競合は停止です。

4.3.2を入れたら、本人に「アップデートして」と言い直してもらわず、同じ依頼の続きとして進めます。導入済みになった4.3.2の道具で `python3 -I tools/release_package.py status --ws .` を実行し、返った最新の完全commitを `fetch --ref` へ渡して `check` します。2段目の差分と保全方針を示して、もう一度「アップデートしますか？」と聞き、OK後に確認窓を出します。2段目の差分は1段目の導入後にしか確かめられないため、1段目のOKで2段目まで承認したことにしません。

## Claudeの設定を保つ

4.3.2候補は公開4.4.0と同一の共通permissionsとautoMemory設定を使い、共通sandboxの必須設定を持ちません。任意設定は `tools/building/templates/claude-sandbox-settings.json` を参照できますが、native Windowsでは有効化しません。対応環境でも既存のlocal設定へ丸ごとコピーせず、保護継続を確認してから本人が選びます。sandboxなしではBashなど間接経路の秘密保護を保証しません。

利用者の `.claude/settings.local.json`、独自スキル、案件内設定は消しません。既に独自sandboxを有効化したlocal・上位設定がある場合、共通設定の変更だけでWindowsの起動が直るとは限りません。内容を外部送信せず、実効設定を本人と確認して停止します。旧共通設定の独自編集も競合のまま保持し、`--overwrite` で回避しません。

## explainer-videoの同名競合

ユーザー版と公式版は22件中3件が異なるという調査結果があり、同一物とは扱いません。同名パスの競合では確認窓の前で停止します。無断の上書き・改名・削除・一時退避はしません。変更済み一覧がGit管理済みでも競合は消えません。

本人が選べる方針は、(1) ユーザー版を保って更新を保留、(2) 差分・既存成果物の相対参照・スキル名を調べ、別名のユーザー版と公式版の共存を別途承認、(3) ユーザー差分と参照先を保全・統合する個別計画を別途承認、です。2/3は現更新器の自動解決機能ではありません。先にバックアップと復元方法を合意し、変更後の再check・両版の選択方法と参照先を検証します。どれも承認前には実行しません。

## 停止理由とTEMP

4.3.2以降の更新器は、Windows確認窓のPowerShellを毎回新しい専用一時フォルダで起動し、終わったら片付けます。固定4.4.0の確認窓は旧実装のため、Windowsのユーザー領域（AppData\Local）を解決できない環境では、作業場の直下に `Microsoft\Windows\PowerShell\ModuleAnalysisCache` が作られることがあります。PowerShellのキャッシュで更新とは無関係です。中身を確かめてから本人の判断で片付け、更新器の検査を迂回しません。

新更新器は範囲外・未commit対象などを総数付きで全件表示します。`check` の標準出力・標準エラーの両方を端末で確認してください。長い表示は端末のローカルログへ保存して全件確認し、秘密や本人データを公開しないでください。旧4.1.0の10件打切り表示は後から変更できないため、この公開README側の案内が入口です。

`.DS_Store`を取り除いて検査を通すのではなく、固定Git blobだけから配布候補を作り、混入したtreeは検査で拒否します。利用者のファイルは削除しません。取得失敗時に今回の専用TEMPの片付けも失敗したら、元の取得エラーを保持して警告します。以前のTEMPを検索・一括削除しません。11月3日の古いTEMP3件は対象外で、本人が内容・使用中プロセス・必要性を確認し、削除を別途了承するまで残します。

## Windows実機の安全な受入れ

本番4.1.0ではなく、架空のWiki・案件・レシピ・偽秘密だけを持つ独立Git検証用フォルダで行います。実秘密をコピーせず、バックアップと履歴復元を先に確認します。本番と通信する試験は公式公開と別承認が必要です。公開前の候補は本番へ使わず、配布者が用意した独立の架空環境だけで試します。

1. Python/Git/gh/Claude Codeの版とnative Windowsであること、共通・local・上位の設定を確認。秘密値は記録しません。
2. 各段階で固定公開commitを取得・旧版checkし、配布hash・対象範囲・Git祖先・個別設定のhashを照合。本人が説明を読んで承認します。
3. 初回の本人端末確認と、以降のWindows窓でキャンセル・timeout・承認をそれぞれ確認。承認以外でファイルが変わらないことも確認します。
4. 各段階でClaudeを新規起動し、架空ファイル編集を確認。偽秘密の直接読取拒否、pushの確認維持を確かめ、間接経路の限界は別記します。実公開や本物の秘密読取を試しません。
5. 22件中3件が異なる架空スキルで停止し全データが不変であることを確認。競合解決は別承認です。TEMPをロックした失敗でも元エラーと警告が残り、旧TEMPが不変であることを確認します。

各段階で不一致なら次へ進まず、記録・plan・hashを本人側に保持して報告します。模擬試験合格はWindows実機の起動保証ではありません。

## 旧更新器の全件点検と共通設定の競合

4.1.0自身と固定4.4.0の取得器・更新器には、10件打切り表示とTEMP片付けの二次エラーによる元エラー隠蔽が残ります。更新後の改善を遡及適用できません。両版でエラーが出たら再取得を重ねず、標準出力・標準エラーを本人の端末内だけで確認し、最初のエラーが分からなければ停止します。古いTEMPは触りません。

本番では以下を本人のローカル端末で実施し、出力をAI・公開ログへ貼り付けません。`--overwrite`や手コピーで先へ進みません。

```powershell
# 読取専用。パス一覧も本人側だけで確認し、外部へ送らない
git status --porcelain=v1 --ignored --untracked-files=all
git diff --name-only
# 共通設定を値なしで照合。導入済み更新器のOS一覧（現行と昔の正式版のhash）と比べ、ネット不要
python -I -c "import hashlib,importlib.util,pathlib; r=pathlib.Path('.').resolve(); s=importlib.util.spec_from_file_location('u',r/'tools/update_os.py'); u=importlib.util.module_from_spec(s); s.loader.exec_module(u); p={}; c,_=u.read_manifest(r,p); h=hashlib.sha256((r/'.claude/settings.json').read_bytes()).hexdigest(); print('shared-settings-recognized:',h==(c or {}).get('.claude/settings.json') or h in p.get('.claude/settings.json',set()))"
```

`False` のときは本人がネット/同期/拡張機能のないローカル編集画面で両ファイルを比較します。値を含むdiffや設定全体をログ化しません。自動マージ/上書き/移動はしません。必要な独自設定と禁止/確認ルールの保持を本人が判断し、判断できなければ値や秘密を送らず「共通設定が競合した」と報告して止めます。localへの移動も保護の意味が変わるため別了承が必要です。
