# 作るための参照Wiki

共通手順版: `building@1`。必要なページだけ読む。個人のWiki本文とは別のOS配布正本で、旧ビルダーの全ハーネスを復元するものではない。

本人の目的から進め方を選ぶ。制作前には `wiki/README.md` の「過去の知識を使う」に従い、合うレシピ・似た案件や知識の原文を探し、出どころと今回に合う理由を添えて活かす。新規制作は小さくてもレシピからでも設計確認を行う。本人が設計提示の省略を明示した場合だけ省ける。目的と完成条件が変わらない小さな修正・文案・一時集計には一律の制作フローを課さない。

了承後は、作る → 動かして確かめる → 直す、を報告まで進める。本人にしか決められないことや安全・復旧の境界でだけ止まる。案件の目的・完成条件・判断と「作り方のメモ」は `wiki/projects/<名前>.md`、成果物は `projects/<名前>/` へ。案件の保存方法は [最小構成](project.md)、記録と履歴保存は `wiki/README.md` に従う。

| いつ | 読むもの | 確かめること |
|---|---|---|
| 新規制作・大きな変更の設計前 | [設計](design.md) | 完成条件・本人了承・出力と復旧 |
| 外部で作った既存案件を管理・継続開発する | [既存案件の接続](existing-projects.md) | 原本保持・配置の選択・Git・独自設定・実行前確認 |
| 継続案件を直接開けるようにする | [最小構成](project.md) | 独立した入口・設定・保存先 |
| 設計の後、作る前に架空のデータで触って確かめる | [作る前の試作](../../.agents/skills/create-prototype/SKILL.md) | 設計のOK・主な流れ1本・`projects/<名前>/prototype/` |
| 見た目のある物を完成と報告する前 | [見た目の確認](../../.agents/skills/design-review/SKILL.md) | 広い幅と狭い幅を撮って `DESIGN.md` と照らす・未確認の区別 |
| 図解・説明動画を作る | [図解](../../.agents/skills/visualize-project-architecture/SKILL.md)・[説明動画](../../.claude/skills/explainer-video/SKILL.md)（Claude Code専用） | 根拠の表・置き場・撮影の可否 |
| Claude/Codexの設定を作る・替える | [AI設定](settings.md) | 対象と実効設定・秘密・承認 |
| スキルを追加・引き継ぐ | [スキル](skills.md) | 共通正本と各AIの探索先 |
| 完成を判定する | [検証](verification.md) | 静的検査・実読込・動作の区別 |
| 古そう・エラー・外部仕様依存 | [方法の見直し](freshness.md) | 公式根拠→候補→試験→記録 |
| 旧レシピを使う | [旧形式の読み替え](legacy-recipes.md)と[レシピの手順](../recipes.md) | 旧依存・安全指示・利用条件 |

設定の実物は [templates/](templates/)、静的検査は `python3 tools/building_check.py --project projects/<名前>`。この道具は案件を生成・変更せず、コマンド・hooks・レシピを実行しない。

新規作成後と旧案件の統合後は、Wikiの「案件」→対象案件の「ダッシュボード」「README」タブへ案内する。[最小構成](project.md)のWiki正本・README入口・AGENTSの更新先をそろえ、別ダッシュボードや説明本文の二重管理を作らない。

本人の経験・環境差は個人Wikiへ「参照した共通手順のIDと版、選んだ理由、実結果」を記録する。配布仕様を個人Wikiへ丸ごと写して二重管理しない。OS更新は個人Wiki・案件・レシピを変更しない。
