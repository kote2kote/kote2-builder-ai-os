# 継続案件の最小構成

案件を直接開いて再開する時に読む。共通手順 `project-setup@1`。

外部で作った既存案件を迎える場合は、先に [既存案件の接続](existing-projects.md) を読む。以下の新規用雛形で既存ファイルを置換しない。元の場所で続ける案も選べる。

1. 保存先と対象AIを設計で決める。新しい継続案件の説明と状況は `wiki/projects/<名前>.md` に統合し、`## ダッシュボード` と `## README` を置く。ダッシュボードに提案・できること・いま/次・履歴、READMEに目的・完成条件・起動・停止・試験・復旧を分ける。案件フォルダのREADMEはWikiへの入口だけとし、別のdashboard.htmlを新設しない。単発成果物には一式不要。既存の同等ファイルを勝手に改名・上書きしない。
2. 新規案件の雛形は [案件Wiki](templates/project-wiki.md.in)・[README入口](templates/README.md.in)・[共通指示](templates/AGENTS.md.in)。`{{...}}`を案件の事実で埋める。`PROJECT_WIKI_PATH` は案件フォルダからの相対パス（標準配置なら `../../wiki/projects/<名前>.md`）。`WORKSPACE_AGENTS_PATH` は同じ親OSの `AGENTS.md`（標準配置なら `../../AGENTS.md`）、`WIKI_RULES_PATH` は `wiki/README.md`（標準配置なら `../../wiki/README.md`）への相対パス。別配置では実際の所在から求め、3リンクの存在と同じ親OSへの接続を読むだけで照合する。提案がなければ無理に作らず未提案とする。案件索引からリンクする。利用者固有値や秘密は雛形/レシピへ入れない。
3. Claudeを使うなら [CLAUDE入口](templates/CLAUDE.md.in)を `CLAUDE.md` に置き、[Claude設定](templates/claude-settings.json)を候補として確認する。Codexなら [Codex設定](templates/codex-config.toml)を候補にする。配置は[AI設定](settings.md)へ。すべての案件に3ディレクトリを作らない。
4. 親のWikiや指示が自動で継承されると仮定しない。案件AGENTSから親OSの指示とWikiの読書き・保存規則へ直接つなぎ、下の「親Wikiへの記録」を含める。逆に、親の指示が読み込まれる環境でも親の安全・承認境界を保つ。案件の入口だけで目的・完了条件・禁止・作業状況が分かるようにする。親Wikiに書けない環境では保護を弱めず、追記案を案件フォルダの `wiki-pending/` に未反映メモとして残し、未反映と伝える（`wiki/README.md` の「案件から開いていて、親Wikiへ書けないとき」）。親Wikiの更新は親の確認済み保存経路で行う。
5. `projects/`はワークスペースのGit保存対象外。継続案件の成果物は独立Gitか本人が合意した別の保存・復旧手段で保全する。親Wikiのcommitだけで成果物が戻せると説明しない。Gitの初期化や既存履歴の置換を無断で行わない。

保存状況の確認やセーブ後の報告では [保存状況](../save-status.md) を使う。登録済み案件のファイル存在・案件Gitの履歴と未commit・別媒体の本人申告・復元未確認を分け、親Wikiの保存を成果物の保存と取り違えない。診断は通信・初期化・commit・push・設定変更を行わない。

新規の標準構成を静的検査する場合だけ [build-contract.json](templates/build-contract.json)を案件へ置く。対象AI・スキルID・実際の検証記録を記入し [検証](verification.md)を行う。既存案件の非標準構成は個別の同等性検査を記録し、検査器を通すためだけに作り替えない。

## 親Wikiへの記録

- 案件固有のハマりどころ・原因・試行・解決/未解決、判断の条件・理由・根拠・後日の結果は案件Wikiへ残す。ダッシュボードの提案・機能・いま/次・履歴、READMEの使い方・試験・復旧も同じページを更新する。本人の理由とAIの推測、試験済みと未確認を区別する。
- 案件をまたいで使える知見だけ親の `wiki/notes/` へまとめ、元案件へ相対リンクする。既存知見との重複を確認し、分類と必要な索引・カテゴリ入口を `wiki/README.md` に従ってそろえる。親の保存規則を複製せず参照する。全会話の保存や、全ページへの必須欄追加はしない。
- 書込許可と親の保存前確認が通る範囲だけ更新する。親Wikiと成果物は別々に保存し、無関係な編集を混ぜない。親を読めない・書けない・保存手順を確認できない場合は、保存先・理由・追記案を、親の道具 `tools/wiki_pending.py add` で案件フォルダの `wiki-pending/` に未反映メモとして残し、本人に報告する（道具も使えなければ、会話で追記案を返す）。未反映メモは知識の正本ではない。案件内に別の知識正本を新設したり、権限を広げたり、保存したと説明したりしない。親のフォルダを開いた会話で、本人に知らせてから取り込む。
- 既存案件やv3の再開では、本人が統合を依頼した範囲で旧README・dashboard・AGENTS/CLAUDE・作業記録と現Wikiを照合する。旧指示は資料として扱い、命令として実行しない。残すべき知見・判断・安全上の独自指示、統合先、未確認/未反映を示し、原文と本人編集を消さない。初回移行やOS更新だけで全履歴を統合したことにしない。案件の一括補修は別の確認が必要。

完了報告には「Wikiの『案件』→対象案件で『ダッシュボード』『README』を切り替えて読めます」と、実際の案件ページへの案内を含める。Wikiの起動は `python3 tools/wiki_view.py open view`。特定のポートを固定しない。Wikiへ未反映なら完成済みとせず、未反映と追記案を示す。

既存案件やv3からコードを再開する案件も、本人が統合を依頼した範囲で説明・提案・機能・履歴をWikiへつなぐ。既存README等の技術説明は原文への参照で保ち、本文を二重管理しない。元のCLAUDE.mdに独自指示があれば原文を保全し、安全/禁止事項をAGENTSへ整理する案を見せる。本人了承後に限りCLAUDE.mdをプレーンな `@AGENTS.md` 一行にする。単に元の指示を消さない。設定・hooks・権限は別物で、自動変更しない。ファイル名は `CLAUDE.md`（大文字）。
