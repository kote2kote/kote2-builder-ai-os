# 設計と完成条件

新しく作る・大きく変える前に読む。共通手順 `design@1`。

短い設計に、目的、本人が確かめられる完成条件、使う技術と理由、AIの推定、本人が用意するものを書く。出力先・使い方・継続案件か単発か・対応AI・外部通信/公開/課金/破壊の境界・保存/復旧の担当も必要な範囲で決める。既存案件では未commit・独自設定の有無を、秘密を読まずに確認する。

設計を見せた返事では作らず、了承を待つ。聞く順番、内部構成、実装順序はAIが判断する。小さな文言修正や一時集計に案件一式を押し付けない。設計承認は外部公開・課金・破壊・権限緩和の包括承認ではない。

継続案件なら [最小構成](project.md)、レシピなら [レシピの手順](../recipes.md)を併用する。完成条件に試験方法を付ける。自動化できない条件は本人が見る項目と未確認の扱いを決め、試験を省略して完成にしない。
