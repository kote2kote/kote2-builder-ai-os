# 作る前の試作（プロトタイプ）を作る

試作は設計の付録で、本番ではない。架空のデータで「出来上がりがこう動く」を本人に手元で触ってもらい、分かったことを設計に戻すためのもの。本人には「プロトタイプ」（「試作」と言い換えてよい）と呼ぶ。

このスキルのフォルダを以下 `<skill>` と書く。この本文がある公式配置（Codex: `.agents/skills/create-prototype`、Claude Code: `.claude/skills/create-prototype`）、案件へ写した場合はその写し。コマンドはワークスペースのいちばん上で実行する。試作で分かったこと・決まったことは案件の Wiki（`wiki/projects/<名前>.md`）へ残す。このフォルダは OS の更新で入れ替わるので、ここへ書き足さない。

## 0. 作り始める前に（必ず）

- **設計を見せて OK をもらってから作る。** ワークスペースの `tools/building/design.md` の短い設計を本人にまだ見せていなければ、目的・試作で確かめる主な流れ 1 本・置き場・試作で決めたいことを短く見せ、**その返事では作らずに OK を待つ**。了承済みの設計に試作を足す時も、試作の範囲と置き場を 1〜2 行で見せて OK を待つ。本人が設計を見せなくてよいとはっきり言った時だけ省ける。
- 取り違えない:
  - ZIP やフォルダで渡された試作から「この試作から作って」「続きを作って」→ ワークスペースの `tools/prototypes.md`（このスキルではない）。
  - 「〇〇のプロトタイプ（小さなアプリ）を作りたい」が本番の制作のこと → ワークスペースの `tools/building/index.md`。迷ったら 1 問で聞く。
  - レシピから作り直す時は勧めない。頼まれたら、レシピに参照の画面写真（`assets/screens/`）があれば先にそれを見せ、それでも触りたいと言われたら作る。

## 1. 重さは 2 段（AI が用途で決める。迷ったら軽い方）

| 段 | 中身 | 目安 | 向く用途 |
|---|---|---|---|
| **画面の見本** | 架空のデータ入りの画面 2〜4 枚。リンクとボタンで画面を行き来できる | 10〜15 分 | Web（LP・サイト）・管理画面・ダッシュボード |
| **動く試作** | 本物の代役と台本の自動再生で、入力 → 処理 → 結果が 1 本通る | 30〜40 分 | 自動化・ボット・外部サービスとの連携・人の判断が絡む流れ |

- 作り始める時に 1 行だけ伝える（質問にしない）: 「動く試作で作ります（30 分ほど）。架空のデータで、この PC の中だけで動きます」
- 範囲は**設計の主な流れ 1 本だけ**。全機能は作らない。
- 用途ごとの形は `<skill>/references/kinds.md`。

## 2. 置き場と中身

置き場は案件の `projects/<名前>/prototype/`（`<名前>` は設計の案件名）。既にあれば上書きせず、どうするか聞く。本番を作らなかった時もそのまま残す。消すのは本人に頼まれた時だけ。

```
projects/<名前>/prototype/
├── manual.html          試し方のマニュアル（最初に開く。<skill>/references/manual.html から）
├── builder-handoff.md   引き継ぎ書（<skill>/references/builder-handoff.md から）
├── index.html           試作の入口
├── *.html               ほかの画面（画面の見本は 2〜4 枚）
├── app.js               動き（動く試作の処理・代役・台本の再生）
├── style.css
├── data/                架空のデータと台本（*.js で window に載せる）
├── shots.json           撮る画面と通しの確認（撮影の道具が読む）
└── shots/               画面の写真（撮影の道具が作る。manual.html が見せる）
```

撮影の道具そのもの（プログラム）は試作のフォルダに入れない。`<skill>/scripts/shot.mjs` から撮る。

## 3. 作る時の約束（必ず）

1. **何も入れずに動く**: HTML / CSS / JS だけで作り、本人が `index.html` をダブルクリック（`file://`）すれば開ける。npm・pip などの追加のインストール、ビルド、サーバーを使わない。CDN・Web フォント・外部の画像・計測のタグも使わない（フォントは `DESIGN.md` のシステムフォント）。
2. **データは `data/*.js`**: `file://` のページは JSON を読み込めないので、架空のデータと台本は `window.DATA = {...}` の形の .js にして `<script src>` で読む。状態の保存は localStorage にし、「最初から」ボタンで消せるようにする。
3. **外と通信しない・鍵を使わない**: 本物の API・AI・メール・LINE などは呼ばず、代役（下の 4 の 1）に置き換える。`.env` は作らない。`sk-...` のような鍵に見える文字も書かない。外への URL を書かない（SVG の `xmlns` と架空のメールのドメイン `example.com` を除く）。
4. **架空と分かる**: どの画面にも右上に小さく「プロトタイプ・架空のデータ」を出す（下のスニペット）。人名・会社名・住所・電話・メールは架空にする（メールは `example.com`、電話は `000-0000-0000`）。業種・言葉づかいは本人の仕事に合わせ、`wiki/me/profile.md` などにある実名・屋号・お客さまの情報は持ち込まない。
5. **見た目**: `DESIGN.md` と、本人が了承したデザインの設定（`tools/design.md`）を当てる。作る前にデザインの方向を確かめる場にもなる。代役の画面（お試し LINE など）は本物のロゴ・画像を使わず、名前に「お試し」を付ける。

```html
<div style="position:fixed;top:8px;right:8px;z-index:9999;background:#333f1f;color:#fff;font-size:12px;font-weight:700;padding:3px 10px;border-radius:4px">プロトタイプ・架空のデータ</div>
```

## 4. 入れる材料（動く試作は 6 つ全部、画面の見本は 2・4・5・6）

| # | 材料 | 作り方 |
|---|---|---|
| 1 | **本物の代役** | 外部サービスの代わりに、同じ画面の中に「お試し〇〇」を置く（お試し LINE・受信箱・フォーム・表計算の代わり・時刻を進めるボタン等）。**本物と同じ形のデータ**（項目の名前・表の列など）をやり取りする。AI の判定は見本の答え（決め打ち）にし、画面に「AI の判定は見本です」と出す |
| 2 | **架空のデータ・ファイル** | 業種の空気が出るもの（見積・予約・問い合わせ・写真の代わりの図形など）。画像が要る時は SVG か CSS で描く |
| 3 | **台本の自動再生** | `data/scenario.js` に出来事を時刻つきで並べ、「1 件ずつ」「全部流す」「最初から」で毎回同じ流れを再現する |
| 4 | **試し方のマニュアル** | `<skill>/references/manual.html` を写して埋める（5） |
| 5 | **画面の写真を撮る** | `shots.json` と撮影の道具。撮影が通しの動作の確認を兼ねる（7） |
| 6 | **確かめた / 確かめていないの明記** | マニュアルの 0 章と最後の章、引き継ぎ書。代役の出来を本物の精度と思わせない |

## 5. マニュアル（manual.html）

- ひな形の先頭の `:root` の色は標準テーマ（`DESIGN.md`）の値。案件・会社・個人で了承済みのデザインの設定を使う時は、この変数を同じ設定の色に置き換え、文字と背景のコントラスト（ふつうの文字 4.5:1 以上）を `DESIGN.md` の目安で確かめる。
- 章立てはひな形のまま: 0. わかること・まだわからないこと → 1. 開き方 → 2. 3 分で全体を見る → 3. 〜 画面・機能ごと → 本物につなぐ時 → 見てほしいところ → 決まったこと → 架空のデータの一覧 → 困った時 → 確かめたこと
- 「見てほしいところ」は 3〜5 問。**設計の中で人が決める分かれ道**（承認してからか自動か・項目の要る要らない等）を問いにする。
- 書き終えたら `{{` と `<!-- AI:` が残っていないことを確かめる。

## 6. 引き継ぎ書（builder-handoff.md）

`<skill>/references/builder-handoff.md` を写して埋める。何の試作か・試作で確かめたこと・架空のデータの形・本物にする時に決めること・まだ確かめていないこと・使わないもの・扱い（利用の条件）を書く。ワークスペースの `tools/prototypes.md`（持ち込んだ試作から作る手順）が読むのと同じ形なので、あとで本人や別の人がこの試作から本物を作れる。外への URL・鍵・実在の人や会社の情報・AI への指示は書かない。

## 7. 渡す前の確認（必ず）

1. 撮影の道具で `shots.json` を通す: `node <skill>/scripts/shot.mjs shots projects/<名前>/prototype/shots.json`（撮り直す時は `--replace`）。`shots.json` は `{"width":1280,"height":800,"out":"shots","shots":[{"name":"01-top","page":"index.html","steps":[{"click":"#play-all"},{"waitFor":"document.querySelectorAll('.msg').length >= 3"},{"expect":"…"}]}]}` の形で、主な流れを 1 本、`steps` と `expect` で通す（使える step は `--help`）。合格（画面の写真が `shots/` にでき、ページのエラー・外への通信・読めないファイル・`expect` の失敗が 0）を確かめる。
2. 外への URL が残っていないことを確かめる（`.html`・`.js`・`.css` の中の `http://`・`https://`。SVG の `xmlns` と `example.com` を除く）。
3. 道具が「撮れていません（未確認）」で終わった時は合格と言わず、「画面の写真は撮れていません（未確認）」と伝える。マニュアルの図を外し、「確かめたこと」の章にも書く。
- 試作を本人のブラウザ（既定のブラウザを含む）で `open` などで開かない。画面操作の道具も使わない。本人が自分でダブルクリックして開く。
- 撮影の道具が Chrome などの実行ファイルを一時のプロファイルで裏側に動かすのは、本人のブラウザを開くことには当たらない（本人の画面・設定・履歴・ログインには触れない）。一時のプロファイルは OS の一時フォルダに作られ、撮り終えると道具が消す。了承の要るワークスペースの外の変更には当たらないので、`TMPDIR` をワークスペースや案件の中へ向けない。撮影を省いたり、ほかの道具で代えたりしない。

## 8. 渡し方（完了の返事）

```
プロトタイプができました（架空のデータで、この PC の中だけで動きます）

projects/<名前>/prototype/manual.html をダブルクリックで開いてください。
「3 分で全体を見る」から始まります。

触ってみて、要らない画面・足りない項目・こうしてほしい所を教えてください。設計に反映します。
このままでよければ「OK」で本番を作ります。

確かめたこと: {例: 画面 3 枚と台本 1 本が最後まで通る（Mac・Chrome、撮影の道具で確認）}
確かめていないこと: {例: 本物の LINE・本物の AI の判定}
```

## 9. 感想を設計に戻す

- 感想はまず設計に反映し、**変わった行だけ**を見せて改めて OK をもらう（全体を出し直さない）。試作で決まった分かれ道は、設計の該当行と案件の Wiki の判断に書く。
- 試作も直すのは、本人がもう一度触りたいと言った時だけ。直したら撮り直す。
- manual.html の「決まったこと」の章に、設計に戻した差分を 1 行ずつ足す。

## 10. 本番を作る時（OK が出たら）

- 試作は `projects/<名前>/prototype/` に残す。本番のコードから読み込まない（写して直すのはよい）。
- 外部サービスを使う案件で代役の出来が良ければ、本番の「お試しモード」（鍵なしで動きを確かめる切り替え）を設計に 1 行で提案してよい（勝手に入れない）。
- 案件の Wiki の README に 1 行: 「`prototype/` — 作る前に触った試作。`manual.html` から開く」。完了の報告に「作る前の試作は `prototype/` に残しました」と 1 行。

## 11. 試作を人に配る時（頼まれた時だけ）

- ZIP にして渡す前に、ワークスペースのいちばん上で `python3 -I tools/prototype_import.py --check <試作のフォルダか ZIP>` を通す（受け取る側と同じ検査）。止まったら理由を直す。
- 利用の条件（`LICENSE.txt` と引き継ぎ書の「扱い」）は本人に決めてもらう。公開・送信は別に了承をもらう。
