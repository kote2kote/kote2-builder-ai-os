# 見た目の確認と直し

見た目に関わる物を作った・直したら、**完了を報告する前にこの確認を回す**。AI はコードを書いた時点では自分の出力を見ていない。見ずに「できました」と言わないための手順。

このスキルのフォルダを以下 `<skill>` と書く。この本文がある公式配置（Codex: `.agents/skills/design-review`、Claude Code: `.claude/skills/design-review`）、案件へ写した場合はその写し。コマンドはワークスペース（または案件）のいちばん上で実行する。分かったこと（崩れやすい所・直し方）は案件の Wiki（`wiki/projects/<名前>.md`）へ残す。このフォルダは OS の更新で入れ替わるので、ここへ書き足さない。

## 回す時・回さない時

- 回す: Webページ・LP・アプリの画面・HTML の資料・HTML のレポートを新しく作った時と、見た目が変わる大きな直しをした時の完了報告の前。本人が「見た目を確認して」「なんか違う」「ダサい」「崩れてない？」と言った時。
- 回さない: 見た目の無い作業、表示に関わらない文言だけの直し、デザイン設定の相談（`tools/design.md`）、作る前の設計、持ち込んだ試作（`tools/prototypes.md` の決まりで開かない）。図解・説明動画・作る前の試作は、それぞれのスキルの確認で済ませ、ここを重ねて回さない。
- スライド・PDF・Word・表計算は、それぞれの形式の道具の確認を使う（HTML で表示できる物だけ、補助にこの手順を使ってよい）。

## 1. 表示する

- ただの HTML は、そのファイルを撮影の道具に渡す。
- 開発用のサーバーが要る案件は、案件の README（案件の Wiki）の起動手順で `localhost` に立てる。撮り終えたら自分で立てたサーバーは止める。
- 本人のブラウザ（既定のブラウザを含む）を `open` などで開かない。画面操作の道具・ブラウザ連携の道具も使わない。本人のプロファイルに触れない撮影の道具だけを使う。

## 2. 撮る

撮影の道具 `<skill>/scripts/shot.mjs`（Node.js 18 以上、追加のパッケージ不要。Chrome・Edge・Chromium のどれかを、一時のプロファイルで裏側で動かす）で、**広い幅 1280px と狭い幅 390px の 2 枚**を撮る。この道具が Chrome などの実行ファイルを一時のプロファイルで裏側に動かすのは、本人のブラウザを開くことには当たらない（本人の画面・設定・履歴・ログインには触れない）。一時のプロファイルは OS の一時フォルダに作られ、撮り終えると道具が消す。了承の要るワークスペースの外の変更には当たらないので、`TMPDIR` をワークスペースや案件の中へ向けない。撮影をほかの変換の道具（画像のライブラリなど）で代えない。撮った画像は OS の一時フォルダに置き、ワークスペースや案件に残さない。

```bash
node <skill>/scripts/shot.mjs widths <HTML のファイル か http://localhost:<ポート>/…> --out {一時フォルダ}/shot --full
```

`{一時フォルダ}/shot-wide.png` と `shot-narrow.png` ができる。縦に長いページは `--full` でページ全体を撮る。撮り直す時は `--replace` を付ける。HTML が読むファイルは、HTML と同じフォルダかその下にある必要がある（外のフォルダや外の URL を読むと不合格）。ほかの使い方は `node <skill>/scripts/shot.mjs --help`。

- 合格: 画像ができ、ページのエラー・外への通信が 0。
- 不合格: 道具が出した理由（ページのエラー・外への通信・横のはみ出し等）を直してから撮り直す。
- sandboxでChromeが起動できない場合は保護を解除しない。ホストの専用プレビューが使えるなら、秘密を含まない成果物だけを隔離セッションで同じ2幅・エラー・横はみ出しの条件で確認できる。本人のログイン済みブラウザは操作しない。適用環境と制約は `tools/safety.md` を参照する。
- 撮れなかった（ブラウザが見つからない等）: 「見た目は未確認」として扱う。そのうえで、本人に頼めるなら 1 行で頼む: 「確認したいので、ブラウザで開いてスクリーンショットを貼ってもらえますか（できればスマホの幅も）」。ブラウザやソフトを勝手に入れない。

撮った画像は、必ず画像として開いて自分の目で見る。

## 3. 基準と照らす

`DESIGN.md` と、本人が了承したデザインの設定（`tools/design.md` で決めたもの。案件・会社・個人の順に近いものを優先）を開き、画像を見ながら確かめる:

- [ ] 文字切れ・重なり・横のはみ出しが無い。狭い幅で崩れていない
- [ ] 日本語のフォントで表示され、文字の大きさ・行の間・見出しの階層が読みやすい
- [ ] 色が `DESIGN.md`（または了承済みの設定）の範囲に収まり、文字と背景のコントラストが読める
- [ ] 指定の無い別のテーマを混ぜていない（紫のグラデーション・意味の無いアイコン・絵文字・背景の柄など）
- [ ] 影・グラデーション・光る表現で情報の階層を代わりにしていない
- [ ] 余白が詰まりすぎていない。1 画面の主役が分かる
- [ ] ボタンなどの操作の部品が押せると分かり、フォーカスが見える
- [ ] 数値・グラフのラベル・単位が読める
- [ ] 案件のデザインの指定（案件の Wiki にあれば）に反していない

旧レシピの見た目の再現を頼まれた時だけ、レシピの参照の画面写真（`assets/screens/`）とも見比べる（ワークスペースの `tools/recipes.md`）。画素の一致は求めない。

## 4. 直して、もう一度見る

- 色・余白・文字の大きさは、共通の設定（CSS の変数など）から直すのを先にする。
- 直したら**必ず撮り直して**確かめる。直して撮り直すのは最大 2 周。3 周目に入りそうなら、残っている論点を本人に見せて判断してもらう。

## 5. 報告する

完了の報告に 1 行入れる: 「見た目を確認しました（1280px・390px）」と、直したところがあれば短く。撮れなかった・確かめられなかった時は「見た目は未確認（理由）」と書く。確かめていないのに確認済みと書かない。
