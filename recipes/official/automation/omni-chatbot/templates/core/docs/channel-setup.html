チャネル接続手順書

{{PROJECT_NAME}} を Slack / Discord / Chatwork / LINE それぞれと繋ぐ手順です。 1 チャネルずつ繋いで動作確認してから次に進むのがおすすめです。

前提: サーバーが起動していて、外から届く公開 URL {{WEBHOOK_BASE_URL}} が決まっていること (ローカルモードなら名前付き Cloudflare Tunnel の https://ホスト名、Workers デプロイなら https://…workers.dev)。 Webhook URL はこの公開 URL の末尾に /webhook/{チャネル名} を付けたものです。

合鍵(キー)の扱い: この手順で発行するキーは、すべてご自身の手で .env に記入します(Workers デプロイの場合はさらに pnpm wrangler secret put {キー名} で登録)。 .env を書き換えたらサーバーを再起動してから次の手順へ(旧プロセスが残っていると新しい値が効きません)。 チャットや AI に値を貼らないでください。

① Slack(メンションに返信)

集める値.env のキー
Bot User OAuth Token(xoxb で始まる)SLACK_BOT_TOKEN
Signing SecretSLACK_SIGNING_SECRET
  1. api.slack.com/apps → Create New App → From scratch → 名前とワークスペースを選ぶ
  2. OAuth & Permissions → Bot Token Scopes に app_mentions:read chat:write im:history を追加
  3. 同ページ上部の Install to Workspace でインストール → 表示された Bot User OAuth Token を控える
  4. Basic Information → App Credentials → Signing Secret を控える
  5. 2 つの値を .env に記入してサーバーを再起動(URL 検証にも署名チェックが掛かるため、この順番を守る)
  6. Socket Mode(左メニュー)が OFF であることを確認(ON だとイベントが Request URL に一切届かない)
  7. Event Subscriptions → ON → Request URL に {{WEBHOOK_BASE_URL}}/webhook/slack を入力(自動で Verified ✓ になる)
  8. Subscribe to bot events に app_mention と message.im を追加 → Save Changes(再インストールを求められたら従う)
  9. 動作確認: チャンネルにボットを招待(/invite @ボット名)して @ボット名 こんにちは

② Discord(/ask スラッシュコマンド)

集める値.env のキー
Public KeyDISCORD_PUBLIC_KEY
Application IDDISCORD_APPLICATION_ID
Bot TokenDISCORD_BOT_TOKEN
  1. discord.com/developers/applications → New Application
  2. General Information で Public Key と Application ID を控える
  3. Bot タブ → Reset Token で Bot Token を控える
  4. 3 つの値を .env に記入してサーバーを再起動
  5. General Information → Interactions Endpoint URL に {{WEBHOOK_BASE_URL}}/webhook/discord を入力して保存(サーバーが起動していないと保存に失敗します)
  6. /ask コマンドを登録する(ターミナルで 1 回だけ実行。.env の値を読み込んで叩きます): 
    source .env
curl -sS -X POST \
  "https://discord.com/api/v10/applications/${DISCORD_APPLICATION_ID}/commands" \
  -H "Authorization: Bot ${DISCORD_BOT_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"name":"ask","description":"AIに質問する","options":[{"type":3,"name":"text","description":"聞きたいこと","required":true}]}'
  7. Installation(または OAuth2 → URL Generator で bot + applications.commands)からサーバーへ招待
  8. 動作確認: サーバーで /ask text:こんにちは
💡 Discord だけ「メンションに返信」ではなく /ask コマンド方式です。 普通のメッセージ受信には常駐接続(24 時間動き続けるプログラム)が必要で、 Webhook 方式の今の構成では受けられないため。常駐 Bot が必要になったら AI に相談してください(拡張できます)。

③ Chatwork(自分宛メンションに返信)

集める値.env のキー
API TokenCHATWORK_API_TOKEN
Webhook トークンCHATWORK_WEBHOOK_TOKEN
  1. ボット用の Chatwork アカウントを用意(自分のアカウントでも試せますが、その場合「自分宛メンション」= あなた宛です)
  2. 右上メニュー → サービス連携 → API Token を発行して控える
  3. 同じくサービス連携 → Webhook → 新規作成:
    • Webhook URL: {{WEBHOOK_BASE_URL}}/webhook/chatwork
    • イベント: 自分宛のメンション(mention_to_me)
  4. 作成時に表示される トークン を控える(これが CHATWORK_WEBHOOK_TOKEN)
  5. 2 つの値を .env に記入してサーバーを再起動
  6. 動作確認: グループチャットで [To:ボットのアカウント] 付きでメッセージを送る

④ LINE(トークに返信)

集める値.env のキー
チャネルシークレットLINE_CHANNEL_SECRET
チャネルアクセストークン(長期)LINE_CHANNEL_ACCESS_TOKEN
  1. LINE Developers コンソール → プロバイダー作成 → Messaging API チャネルを作成(LINE 公式アカウントが紐づきます)
  2. チャネル基本設定 → チャネルシークレット を控える
  3. Messaging API 設定 → チャネルアクセストークン(長期) を発行して控える
  4. 2 つの値を .env に記入してサーバーを再起動
  5. 同じ Messaging API 設定で:
    • Webhook URL: {{WEBHOOK_BASE_URL}}/webhook/line を入力 → 検証ボタンで「成功」を確認 → Webhook の利用を ON
    • 応答メッセージ(自動応答)を OFF(LINE Official Account Manager 側の設定。ON のままだと定型文が二重に返ります)
  6. 動作確認: QR コードでボットを友だち追加してトークで話しかける

繋がらない時は

  • このフォルダを AI で開いて「疎通テストして」と話しかける(チャネルごとの確認手順を AI が一緒にたどります)
  • まず {{WEBHOOK_BASE_URL}}/ をブラウザで開き、本文が「{{PROJECT_NAME}} is running」であることを見る(200 でも本文が別プロジェクトなら、トンネルの向き先ポートを他のプロセスが先取りしています)
  • ログを見る: ローカルモードはサーバーを起動したターミナル / Workers デプロイは pnpm wrangler tail
  • よくある原因: .env 更新後の再起動忘れ(旧プロセスがポートに居座ったまま)/ Slack の Socket Mode が ON / Workers デプロイでの secret put 忘れ / Webhook URL の末尾チャネル名の打ち間違い
